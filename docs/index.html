Why goforge? Key Engineering Advantages

1. Synchronous Code, Non-Blocking M:N Execution

Every HTTP connection runs in a lightweight gorun green routine. Inside handlers and services you write straightforward sequential C++ with gorun::Mutex, gorun::RwMutex, gorun::Channel, and non-blocking sockets — without callback hell or viral co_await function coloring.

2. Compile-Time Typed DI with Fail-Fast Graph Validation

Unlike reflection-based Go containers that panic at runtime on missing or cyclic wires, ServiceCollection::build() verifies missing dependencies, runs 3-color DFS cycle detection (printing the exact A -> B -> C -> A chain), and blocks captive Singleton -> Scoped leaks at startup.

3. Automatic Per-Request ServiceScope Injection

Declare route handlers like [](HttpContext& c, IUserRepo& repo, RequestTrace& trace). goforge creates an isolated ServiceScope per HTTP request, injects Singletons and Scoped services automatically, and deterministically destroys Scoped objects when the request finishes.

4. Built-In Shield Against Blocking Drivers (BlockingPool)

Need to call a synchronous C library like libpq or sqlite3? Wrap it in blocking_pool.run([&]{ return db_query(); }) — the blocking syscall executes on a dedicated OS pool while your green routine parks cleanly on a gorun::Channel, leaving all gorun workers free.

5. 142,643 req/s, 69 us p50 & 48.4 ms at 300 Concurrent I/O

Powered 100% natively by gorun::net (Windows IOCP, Linux epoll, macOS kqueue — zero Asio dependency!). Under 300 simultaneous I/O-bound connections, goforge completes 300/300 in 48.4 ms on a fixed M:N worker pool (21% faster than 300-thread std::jthread at 61.6 ms). On Keep-Alive JSON APIs, goforge hits 142,643 req/s (p50 = 69 us) — 3.36x faster RPS and 7.6x lower median latency than Go 1.27, and +17% faster RPS than raw Classic Async Asio (122,001 req/s).

6. Production-Ready Out of the Box

Includes recovery panic isolation, timeout (504 via gorun::Context), rate_limit (gorun::Semaphore backpressure or 429), bearer_auth, RFC-8259 StructuredLogger, JSON/Prometheus MetricsRegistry, Kubernetes /healthz & /readyz, and SIGINT/SIGTERM graceful draining.

Recommended for CMake projects — automatically pulls goforge v0.4.0, gorun v0.4.0, nlohmann/json, and embedded SQLite 3 (pass -DGOFORGE_ENABLE_SQLITE=OFF if you do not need SQLite):

add_executable(my_service main.cpp)
target_link_libraries(my_service PRIVATE goforge::goforge)

|  - BlockingPool (Offloads synchronous DB/disk I/O off workers)    |

                                  v

                                  | Green Routines, Channels, Sync
                                  v
+-------------------------------------------------------------------+
|                       gorun Runtime (M:N)                         |
|  - Work-stealing scheduler, Channel<T>, Mutex, WaitGroup, Context |
|  - Native Async NetPoller (gorun::net: IOCP / epoll / kqueue)     |

Complete Usage Guide: How to Build Services with goforge

1. Fx-Style Dependency Injection (Singleton, Transient, Scoped)

Wire interfaces, constructors, factories, and pre-built configuration structs with automatic type-based argument resolution:

auto app = goforge::AppBuilder{}
    .provide_instance(ServiceConfig{ .db_dsn = "postgres://127.0.0.1/orders" })
    .provide_singleton<goforge::obs::StructuredLogger>()
    // Bind interface IUserRepository to PostgresUserRepo with automatic constructor DI:
    .provide_singleton_as<IUserRepository, PostgresUserRepo, const ServiceConfig&, goforge::BlockingPool&>()
    // Scoped: created fresh per HTTP request and destroyed deterministically on request end!
    .provide_scoped<RequestTrace>()
    // Transient: fresh instance on every resolution
    .provide_transient<CorrelationToken>()
    .build(); // Validates missing deps, cycles (A -> B -> A), and captive scopes!

2. Lifecycle Hooks, Background Routines & Graceful Shutdown

Inject goforge::Lifecycle& directly into any service constructor or invoke(...) callback. Hooks start in FIFO order (with automatic reverse rollback if any hook fails) and stop in LIFO order on SIGINT/SIGTERM:

lc.append({
    .name = "database-pool",
    .on_start = [this](gorun::Context ctx) { connect_pool(ctx); },
    .on_stop  = [this](gorun::Context ctx) { close_pool(ctx); }
});

// Managed background green routine: canceled automatically via ctx.on_done() during App::stop()
app->spawn_background([](gorun::Context ctx) {
    gorun::Channel<int> never_ch(0);
    gorun::select(
        never_ch.on_recv([](int) {}),
        ctx.on_done([]() { std::cout << "Background worker drained cleanly\n"; })
    );
});

app->run_until_signal(); // Handles Ctrl+C / SIGTERM with full connection draining!

3. Ergonomic WebApp, Zero-Lambda Controllers & Fluent Query AST

Skip boilerplate wiring and verbose C++ lambdas: bind controller methods directly with typed extractors (Body<T>, Path<"id", int>, Query<"q">, Header<"X-Api-Key">), return DTOs / std::optional<T> / Page<T> directly, and query data with C#/EF-style compile-time Expression Trees (col(&User::age) >= 18, it > 10, or GF_FN):

using namespace goforge;
using namespace goforge::query;

struct User {
    int id{0};
    std::string name, email, role{"user"};
    int age{0};
    bool active{true};
    std::optional<std::string> bio;
};
GOFORGE_MODEL_TABLE(User, "users", id, name, email, role, age, active, bio)

struct UserController {
    IUserRepo& repo;
    explicit UserController(IUserRepo& r) : repo(r) {}

    ApiResponse create(Body<CreateUserDto> dto) { return created(repo.create(*dto)); }
    std::optional<User> get(Path<"id", int> id) const { return repo.find(*id); }
    Page<User> list(Query<"q"> q, Query<"min_age", int> min_age) const {
        return from(repo.all())
            .where(col(&User::active) == true && col(&User::age) >= min_age.value_or(0))
            .where(col(&User::name).icontains(q.value_or("")))
            .order_by(&User::role)
            .then_by_desc(&User::age)
            .paginate(1, 20); // Auto-serializes to paginated JSON!
    }
};

auto app = WebApp::create({.port = 8080})
    .singleton<IUserRepo, MemoryUserRepo>()
    .use_defaults();

app.controller<UserController, IUserRepo>("/api/v1/users")
   .post("", &UserController::create)
   .get("", &UserController::list)
   .get("/:id", &UserController::get);

app.run();

5. Safe Blocking Database Calls with BlockingPool

std::string query_legacy_postgres(goforge::BlockingPool& pool, int user_id) {
    // Runs blocking C driver call on dedicated OS pool while parking this green routine!
    return pool.run([user_id]() {
        return libpq_sync_select_user(user_id); // Never stalls gorun M:N workers!
    });
}

6. EF-Style ORM (goforge::data: DbContext, DbSet<T> & SQLite 3)

The exact same goforge::query Expression Tree compiles directly to parameterized SQL across SQLite, PostgreSQL, and MySQL — offloaded onto BlockingPool automatically:

using namespace goforge::query;
using namespace goforge::data;

auto sqlite = SqliteDriver::open("app.db");
DbContext db(sqlite, blocking_pool);
db.ensure_created<User>(); // Auto CREATE TABLE IF NOT EXISTS from GOFORGE_MODEL_TABLE

User u{0, "Artur", "artur@goforge.dev", "admin", 25, true, "Creator"};
db.add(u);
db.save_changes(); // Transactional INSERT + auto-populates u.id!

auto page = db.set<User>()
    .where(col(&User::age) >= 18 && col(&User::role).in({"admin", "mod"}))
    .order_by_desc(&User::age)
    .paginate(1, 20); // Parameterized SQL COUNT(*) + LIMIT/OFFSET -> JSON Page<User>!
